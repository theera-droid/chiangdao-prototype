# Chiang Dao — Vue + JavaScript + Node.js

โปรเจ็กต์ Vue + Node.js รองรับทั้งการรันในเครื่องและ GitHub Pages อ่านเฉพาะยอดรายวัน ไม่สร้างการจอง ไม่ส่งคำขอรหัส และไม่อ่านข้อมูลผู้จอง

## GitHub Pages

เว็บไซต์: https://theera-droid.github.io/chiangdao-prototype/

Workflow `.github/workflows/pages.yml` ทดสอบ อ่านยอดจริง และ deploy เมื่อ push main, กด Run workflow หรือถึงรอบประมาณทุก 5 นาที (GitHub อาจเริ่มช้า จึงไม่ใช่ real time) scheduled run หลัง 13 ก.พ. 2570 จะข้ามงานอ่านข้อมูลและ deploy

Actions อ่านครั้งละไม่เกิน 3 วันพร้อมกัน เว้นช่วงเริ่มแต่ละชุดอย่างน้อย 1.25 วินาที และส่งผลทั้งเดือนเป็นชุดเดียว ชุดข้อมูลมีเวลาที่อ่านสำเร็จแยกรายวัน ไม่ใช่ snapshot ณ วินาทีเดียวกันจากต้นทาง

ก่อนอัปเดตจะอ่านชุดที่เผยแพร่ครั้งก่อนเพื่อเก็บยอดเก่า หากต้นทางล่มจะคงยอดและเวลาเดิมพร้อมป้ายข้อมูลเก่า หากไม่มีข้อมูลใช้ได้เลยหรืออ่านชุดก่อนหน้าไม่ได้ (ยกเว้น 404 ครั้งแรก) จะไม่แทนที่ deployment เดิม หน้า Pages ตรวจไฟล์ชุดใหม่ทุก 30 วินาทีโดยไม่เรียก API ต้นทางจากเบราว์เซอร์

หน้า Pages แสดงยอดที่อายุเกิน 10 นาทีเป็นข้อมูลเก่า และแสดงเวลาแต่ละวันเสมอ ไม่รับรองยอดปัจจุบันหากต้นทางเข้าไม่ได้ ส่วนโหมด Node.js ในเครื่องใช้เกณฑ์ 1 นาที

## รันในเครื่อง

ใช้ Node.js 22.18+ หรือ 24.12+:

```sh
npm install
npm run dev
```

เปิด http://127.0.0.1:5173 กด Ctrl+C เพื่อหยุด บน PowerShell ใช้ `npm.cmd` แทน `npm` ได้ ทั้ง frontend และ backend รับการเชื่อมต่อเฉพาะ 127.0.0.1

```sh
npm test
npm run build
npm start
```

หลัง build เปิด http://127.0.0.1:3001 ได้ ไม่มีขั้นตอน deploy

## การอ่านยอดจริง

- Node.js เตรียมเดือนพฤศจิกายนไว้เมื่อเริ่ม server หน้าเว็บอ่าน snapshot ของเดือนที่ดูจาก `GET /api/availability/month?month=2026-11` โดยไม่ต้องรอต้นทาง เมื่อมีข้อมูลเก็บแล้วจะเห็นยอดทันที
- การเปิดดูซ้ำหรือหลายแท็บใช้ snapshot และงานอัปเดตชุดเดียวกัน ไม่เพิ่มการเรียกต้นทางตามจำนวนผู้ดู
- เก็บยอดจริงและเวลาที่ตรวจได้ใน `.cache/availability.json` เพื่อใช้ต่อหลังรีสตาร์ต (ไม่รวมใน Git) ถ้ายอดเก่าจะติดป้ายและอัปเดตเบื้องหลัง ไม่เปลี่ยนเวลาเก่าให้ดูเหมือนเพิ่งตรวจ
- หากยังไม่มีข้อมูลของเดือนนั้น จะเริ่มเตรียมครั้งแรก อ่านพร้อมกันสูงสุด 3 วันต่อชุด และเริ่มชุดห่างกันอย่างน้อย 1.25 วินาที ไม่อ้างว่ายอดใหม่จากต้นทางพร้อมทันที เปลี่ยนยอดที่แสดงทั้งเดือนเมื่ออ่านรอบนั้นเสร็จ หากวันใดผิดพลาดคงยอดเก่าพร้อมป้ายกำกับ
- คลิกวันเพื่อดูรายละเอียดเท่านั้น เปลี่ยนเดือนจะใช้ snapshot ของเดือนใหม่ หากยังไม่มีข้อมูลจะเข้าคิวงานเบื้องหลังร่วมกัน
- `GET /api/availability?date=2026-11-16` อ่านผ่าน Node.js โดยจำกัดวันตามตาราง 16 พ.ย. 2569 – 12 ก.พ. 2570 ยกเว้นวันพุธ ตารางนี้อ้างอิงโค้ดหน้าเลือกวันที่ตรวจเมื่อ 29 ต.ค. 2569 และไม่ได้ปรับฤดูกาลให้อัตโนมัติ
- ต้นทางยอด: `https://q.wildlifesanctuaryfca16.com/api/v1/bookings/availability?date=YYYY-MM-DD`
- ต้นทางสถานะเปิดระบบ: `https://wildlifesanctuaryfca16.com/api/chiangdao/open` อ่าน `data.q.open` แยกจากยอดที่ว่าง
- พักยอดในหน่วยความจำ 60 วินาทีต่อวัน รวมคำขอซ้ำวันที่เดียวกัน และจำกัดงานอ่านรายวันพร้อมกันไม่เกิน 3 งาน
- เซิร์ฟเวอร์ตรวจซ้ำเมื่อยอดรายวันอายุประมาณ 1 นาที ถ้าหลายเดือนเข้าคิวหรือต้นทางช้าอาจใช้เวลานานกว่านั้น ไม่รับประกันว่ายอดเปลี่ยนตรงกับต้นทางทุกวินาที
- โหมดในเครื่องรับชุดข้อมูลเดือนใหม่ผ่าน SSE (`GET /api/availability/events?month=2026-11`) เมื่ออ่านรอบนั้นเสร็จ ไม่รอรอบ polling 2–10 วินาที งานอ่านต้นทางยังใช้ร่วมกันระหว่างผู้ดู
- เก็บยอดที่เคยอ่านใน localStorage เพื่อแสดงทันทีเมื่อเปิดซ้ำ แม้ backend ยังไม่ตอบ โดยติดป้ายยอดเก่าเสมอจนกว่า server จะส่งข้อมูลมายืนยัน เก็บเวลาที่ต้นทางอ่านสำเร็จเดิมไว้ทุกกรณี
- ติดตามเดือนที่มี stream เปิดอยู่ เมื่อปิด stream จะหยุดติดตามหลังไม่มีการเปิดดูครบ 10 นาที
- หากได้ HTTP 401/403/429 จะพักเรียกต้นทาง 5 นาที ไม่ลองหลบระบบป้องกัน
- หากอ่านผิดพลาดต่อเนื่อง 3 ครั้งจะพัก 1 นาทีแล้วลองใหม่ ไม่ไล่รอ timeout ทุกวันเมื่อระบบต้นทางล่ม
- ถ้าอ่านไม่ได้หรือรูปแบบข้อมูลผิด จะแสดงว่าไม่ทราบยอด หากมียอดเก่าจะแสดงป้ายยอดเก่าและเวลาเดิม ไม่แทนด้วยศูนย์
- วันที่สีเทาคือไม่เปิดตามตาราง ไม่ได้แปลว่าเต็ม ยอดที่อ่านได้ไม่กันสิทธิ์และไม่รับรองว่าจองได้ โดยเฉพาะช่วงต้นทางปิดรับรหัส
- ไม่มีข้อมูลจำลอง fallback ในแอปปัจจุบัน สำเนา HTML รุ่นเดิมอยู่ใน `legacy/` เพื่ออ้างอิงเท่านั้น

นี่เป็นการเชื่อมช่องทางที่หน้าเว็บเรียกใช้ ไม่ใช่ API สาธารณะที่มีเอกสารรับรอง อาจเปลี่ยนหรือหยุดใช้ได้ การทดลองสำเร็จไม่ได้เป็นหลักฐานว่าได้รับอนุญาตให้นำไปเผยแพร่หรือดึงข้อมูลจำนวนมาก

## ไฟล์หลัก

- `src/App.vue`: Vue Composition API, ปฏิทิน, สถานะข้อมูลเก่า/ผิดพลาด
- `server/availability.js`: อ่านและตรวจข้อมูลจริง, cache, timeout, backoff
- `server/snapshots.js`: งานอัปเดตที่ใช้ร่วมกัน, snapshot ในหน่วยความจำและดิสก์
- `src/saved-data.js`: กู้ยอดล่าสุดในเบราว์เซอร์โดยไม่เปลี่ยนข้อมูลเก่าเป็นข้อมูลสด
- `server/app.js`: Express route ภายในเครื่อง
- `server/api.test.js`: tests ใช้ responses จำลอง ไม่เรียกต้นทางจริง
- `scripts/dev.js`: รัน Vite และ Node.js ด้วยคำสั่งเดียว
