# Chiang Dao — Vue + JavaScript + Node.js

ต้นแบบทดลองในเครื่อง ไม่เผยแพร่ แสดงยอดจริงที่ Node.js เก็บไว้ทันที และอัปเดตจากต้นทางเบื้องหลัง ไม่สร้างการจอง ไม่ส่งคำขอรหัส และไม่อ่านข้อมูลผู้จอง

## รันในเครื่อง

ใช้ Node.js 22.18+ หรือ 24.12+:

```sh
npm install
npm run dev
```

เปิด http://127.0.0.1:5173 กด Ctrl+C เพื่อหยุด บน PowerShell ใช้ `npm.cmd` แทน `npm` ได้ ทั้ง frontend และ backend รับการเชื่อมต่อเฉพาะ 127.0.0.1

```sh
npm test
npm run build
npm start
```

หลัง build เปิด http://127.0.0.1:3001 ได้ ไม่มีขั้นตอน deploy

## การอ่านยอดจริง

- Node.js เตรียมเดือนพฤศจิกายนไว้เมื่อเริ่ม server หน้าเว็บอ่าน snapshot ของเดือนที่ดูจาก `GET /api/availability/month?month=2026-11` โดยไม่ต้องรอต้นทาง เมื่อมีข้อมูลเก็บแล้วจะเห็นยอดทันที
- การเปิดดูซ้ำหรือหลายแท็บใช้ snapshot และงานอัปเดตชุดเดียวกัน ไม่เพิ่มการเรียกต้นทางตามจำนวนผู้ดู
- เก็บยอดจริงและเวลาที่ตรวจได้ใน `.cache/availability.json` เพื่อใช้ต่อหลังรีสตาร์ต (ไม่รวมใน Git) ถ้ายอดเก่าจะติดป้ายและอัปเดตเบื้องหลัง ไม่เปลี่ยนเวลาเก่าให้ดูเหมือนเพิ่งตรวจ
- หากยังไม่มีข้อมูลของเดือนนั้น จะเริ่มเตรียมครั้งแรกและทยอยแสดงยอด เว้นอย่างน้อย 1.5 วินาทีระหว่างวัน ไม่อ้างว่ายอดใหม่จากต้นทางพร้อมทันที
- คลิกวันเพื่อดูรายละเอียดเท่านั้น เปลี่ยนเดือนจะใช้ snapshot ของเดือนใหม่ หากยังไม่มีข้อมูลจะเข้าคิวงานเบื้องหลังร่วมกัน
- `GET /api/availability?date=2026-11-16` อ่านผ่าน Node.js โดยจำกัดวันตามตาราง 16 พ.ย. 2569 – 12 ก.พ. 2570 ยกเว้นวันพุธ ตารางนี้อ้างอิงโค้ดหน้าเลือกวันที่ตรวจเมื่อ 29 ต.ค. 2569 และไม่ได้ปรับฤดูกาลให้อัตโนมัติ
- ต้นทางยอด: `https://q.wildlifesanctuaryfca16.com/api/v1/bookings/availability?date=YYYY-MM-DD`
- ต้นทางสถานะเปิดระบบ: `https://wildlifesanctuaryfca16.com/api/chiangdao/open` อ่าน `data.q.open` แยกจากยอดที่ว่าง
- พักยอดในหน่วยความจำ 5 นาทีต่อวัน รวมคำขอซ้ำวันที่เดียวกัน จำกัดงานอ่านพร้อมกัน และเว้นเริ่มงานอย่างน้อย 1.2 วินาที
- เซิร์ฟเวอร์อัปเดตเดือนที่มีผู้ดูประมาณทุก 5 นาทีหลังจบรอบก่อนหน้า และหยุดติดตามเดือนนั้นเมื่อไม่มีการเปิดดู 10 นาที หน้าเว็บอ่าน snapshot ภายในเครื่องทุก 2 วินาทีขณะเตรียมข้อมูล หรือทุก 10 วินาทีเมื่อพร้อม การอ่าน snapshot ไม่ได้เรียกต้นทางโดยตรงทุกครั้ง
- หากได้ HTTP 401/403/429 จะพักเรียกต้นทาง 5 นาที ไม่ลองหลบระบบป้องกัน
- ถ้าอ่านไม่ได้หรือรูปแบบข้อมูลผิด จะแสดงว่าไม่ทราบยอด หากมียอดเก่าจะแสดงป้ายยอดเก่าและเวลาเดิม ไม่แทนด้วยศูนย์
- วันที่สีเทาคือไม่เปิดตามตาราง ไม่ได้แปลว่าเต็ม ยอดที่อ่านได้ไม่กันสิทธิ์และไม่รับรองว่าจองได้ โดยเฉพาะช่วงต้นทางปิดรับรหัส
- ไม่มีข้อมูลจำลอง fallback ในแอปปัจจุบัน สำเนา HTML รุ่นเดิมอยู่ใน `legacy/` เพื่ออ้างอิงเท่านั้น

นี่เป็นการเชื่อมช่องทางที่หน้าเว็บเรียกใช้ ไม่ใช่ API สาธารณะที่มีเอกสารรับรอง อาจเปลี่ยนหรือหยุดใช้ได้ การทดลองสำเร็จไม่ได้เป็นหลักฐานว่าได้รับอนุญาตให้นำไปเผยแพร่หรือดึงข้อมูลจำนวนมาก

## ไฟล์หลัก

- `src/App.vue`: Vue Composition API, ปฏิทิน, สถานะข้อมูลเก่า/ผิดพลาด
- `server/availability.js`: อ่านและตรวจข้อมูลจริง, cache, timeout, backoff
- `server/snapshots.js`: งานอัปเดตที่ใช้ร่วมกัน, snapshot ในหน่วยความจำและดิสก์
- `server/app.js`: Express route ภายในเครื่อง
- `server/api.test.js`: tests ใช้ responses จำลอง ไม่เรียกต้นทางจริง
- `scripts/dev.js`: รัน Vite และ Node.js ด้วยคำสั่งเดียว
